# DEV-027: Fluxo de estados das issues sem saltos

Resposta à questão 7 do README §14 (21-10-2026): as issues têm de passar por todas as fases.

- Avanço só para o estado seguinte: `todo` → `in_progress` → `code_review` → `testing` → `done`.
- Retrocessos atuais mantêm-se (`in_progress` → `todo`, `code_review` → `in_progress`, `testing` → `in_progress`/`code_review`, `done` → `in_progress`).
- Reabrir: a aplicação tem um único utilizador (o gestor), que faz todas as alterações; sem regra adicional.
- Definição de `Done`: manter as regras atuais (sem pré-condições).
- Alterar backend (`domain/issues.py`), frontend (`services/issues.ts`) e testes.
